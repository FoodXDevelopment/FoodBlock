# Stage 7 (last): where `07-last.md` is silent, and what the oracle built

Written by the oracle builder (`spec/oracle/fb.cjs`, plus `spec/oracle/dealer.cjs` and `spec/oracle/readback/`; stories in `spec/oracle/stage7/`), without reading the Rust core. Each entry: the section of `07-last.md`, the reading chosen (the one nearest the centre: only a signed word binds, and only its signer; nothing fills anyone's silence; a later word takes back nothing already built on; simplest wins), and the story that pins it. Marks: C = the text conflicts with another text, S = silent, N = not built. Three builders worked in parallel (the main one, the dealer, the read-back); the last two lists are theirs, joined.

## Conflicts between texts (4)

**C1. `3a-5` against `nodes.md` line 37 (A2).** 3a-5's world has a relay answer Sam's pull for a body whose audience it cannot read with `{ header, header_signature }`. A2 (kept from 1.8) says an unsigned pull gets public blocks, a signed pull also gets each sealed block the node holds a copy of for the asker, and "nothing of a sealed block goes to any other asker, and for anyone else it matches no filter". Built: A2 (the later text, and the privacy one: what I do not send, no one learns from me). Sam gets nothing; Maria, for whom a copy is held, gets it as it came. The 3a-5 story was changed to say so. Pinned: `core-set-a/3a-5.cjs`, `stage7/7-privacy.cjs` (A1).

**C2. G18 `at_most` against the read-back's line 10.** Maria's till grant names the same 40 loaves in `scope.on` (a promise of 40) and in `refs.what` (an instance with a pack of 40). Stage 4's `worst_case` counts them as two measures and gives 80 loaves. The read-back builder read G18 as 40 (one 40 sold once). Not changed: stage 4's answers are agreed in both engines. The line copies whatever `worst_case` says. The text should say whether a promise and the instance it sells from are one measure. Pinned: `stage7/7-readback-lines.cjs` (C4 line 10 at a grant).

**C3. `state.inputs`, one word with two meanings.** C3 (read-back) says `state.inputs` is a sorted list of ids; 00-shared (a make) says `state.inputs: [{ from, amount }]`. Built: the make's shape is a transform's alone, and a `readback` observe carries its list of ids. Without this, every read-back that carries inputs is `shape`. The text should rename one (the read-back's field is the one that is new). Pinned: `stage7/7-readback.cjs` (C3 A).

**C4. `protocol.json` moved under the build.** During the build `door.ops` gained `readback`, `render` and `readback_redo` (with shapes of their own: `readback(block, held, renderer?, digits?)`, an answer whose ids are `{ id, code, name }`, `readback_redo` giving `{ same, readback, lacks, not_run }`), `door.protocol` and `door.classes`. 07-last §6 says "the read-back adds no door op". The oracle reads `protocol.json` as it finds it; it has no door op for those three and its read-back is a library (`spec/oracle/readback/`) with its own shapes (below). Not wired, so the two shapes show as a disagreement when the engines are compared; the text should say which.

## Readings (S)

**S1. B1, `rule_set(files)`.** The argument is a map of path to the file's text (`protocol.json`'s own line: "the file's bytes as text"); bytes are its UTF-8. The manifest names exactly the paths given and judges none (a library tool; it is not told which files are the protocol's). The id is the SHA-256, lowercase hex, of the manifest's canonical bytes (`jcs`). Pinned: `7-rules` (B1).

**S2. B5, `spec` and `rule_set`.** The id of the build's rule set is the id of the manifest published beside the spec (`spec/rule-set.json`); where there is no such file it is `null` ("a build given no manifest"). Today it is `null`. Pinned: `7-rules` (B5).

**S3. B5, `read` with `runs`.** `runs` is a list of 64-hex ids, else an argument error; null or left out is none. A block that states a set in `runs` is read by the core's rules (the core has no later rule); one that states another is `unknown_rules`. Only `read` takes `runs`; the folds still run none. Pinned: `7-rules` (3a-13 and B5).

**S4. B2, the discovery document.** `announcement` (the local one) carries `reads` where it carried `version`. `wellKnownErrors` reads `protocol.json`'s `messages.discovery` as it stands (`reads`, no `version`, `sound` or `speaks_for`). Pinned: `7-rules` (B2).

**S5. A1, the sizes of a padded plaintext.** A sealer that pads gives `seal` the option `{ pad: true }`; the plaintext `{ block, reveals, pad }` is padded so that its own bytes, the `pad` key included, are exactly the next of 512, 1024, 2048, 4096, then each 4096 (so 600 bytes of order is a 1024-byte plaintext, 5,000 is 8192). The size is the plaintext's, not the ciphertext's (that is 16 bytes more). Library `padPlain`, `padSize`. Pinned: `7-privacy` (Sealed messages).

**S6. A1, the shape of a wrapped copy.** `{ mailbox, envelope }`: `mailbox` the reader's public encryption key as she gave it; `envelope` the sealed plaintext `{ copy, pad }` (padded to the sizes above) to that key. What a host that keeps it holds is `{ mailbox, bytes, at }`, `bytes` the envelope's ciphertext length (padded plaintext plus the 16-byte tag, so 4112 when the inner copy pads to 4096). The text's world (an order A2 to Harry) gives 4112 only if A2's sealed copy is between 2049 and 4096 bytes once padded; the story's A2 carries 900 bytes of text for that. Library `wrapCopy`, `unwrapCopy`, `wrappedSeen`. Pinned: `7-keeping` (Keeping apart).

**S7. A2, A6, a node's admission rule for copies.** The door `accept` takes its stated choices in the third argument, as it takes `takes_pairs`: `admission: { copies: [ways], mailboxes: [keys] }`, with the push's `for`, `signer` and `at`. The ways are `signed` (a copy for a named reader is kept from a signed push) and `given_key` (a wrapped copy is kept where its mailbox is one the rule names). A node that states none keeps no copy. The answer gains `kept: [{ for, hash }]` and `wrapped: [{ mailbox, bytes, at }]` only when an `admission` is given; a wrapped copy is no block, so it is neither taken nor refused. A handed-on copy is kept for the reader the push names and never takes the place of the author's. Pinned: `7-keeping` (A2).

**S8. A2, a receipt to a pusher.** Library `receiptFor(taken)`: an `observe` of kind `receipt` whose `derives_from` is the sorted ids that one push added. A batch of two pushes in one second makes two receipts. Pinned: `7-keeping` (A2).

**S9. B1, typed schema fields.** A schema's `fields` is an object `{ name: spec }` or a list of `name:spec` lines; a spec is `text`, `hash`, `id`, `time`, `date`, `duration`, `decimal`, `amount`, `count` or `in:a,b,c` (one comma list), a trailing `!` asking for the field; any other spec is a hint and checks nothing. The name may be a dotted path. A block of any type that names a held schema (`refs.schema`) and carries the field in another shape is `shape`; one that lacks a `!` field is `required`; a schema not held is `names_missing` (for the types `needs` names it). Only `read`, never `valid`. Pinned: `7-schema`, `7-rules` (F, late schema).

**S10. D6, the machine lock.** A machine lock is a grant of kind `stop` with `refs.subject` the machine, no status, no answer, that counts and stands. It is in `locks` when the machine's owner (the ownership fold, in the lock's causal past) backs it (his block, or one under a grant of his that covers `grant.stop` and the machine); otherwise in `claimed`. Both lists are block ids, sorted. It ends by its author's stop, or (as `protocol.json` still says) when its `scope.until` has passed the reader's `now`. `how`, `placer`, `safe`, `reach` and `checked` are undeclared fields; `lifted` is no status. Pinned: `7-rules` (lock).

**S11. Job F, the mount.** A mount is 16 random bytes in hex. `mount(blocks, into?)` adds by block id (a sealed message by its own bytes), so a block given twice is one. A 32-hex text that was never a mount is read as the text it is; one that was and was unmounted is an argument error `unknown_mount`. The memo the 1.8 text asks for (judge once) is not built: a mount keeps the set, and every op reads it as an array (it changes no answer). Pinned: `7-rules` (F).

**S12. C5, "the first block it did not read".** A reader's own limit is a library setting, `setReadLimit(n)` (no door argument names it, 3d-12 said the same of belief). Where a walk of makes stops at it, `lacks` is `[<the make that made the thing it would read next>, { stopped: "depth" }]`; the reason keeps the shape 3a decided (SILENT 4). A walk the machine's own stack stops (a `RangeError`) knows no block and gives only `{ stopped: "depth" }`. With a limit of N makes the first make not read is the (N+1)th from the jar. Pinned: `7-oldreader`.

**S13. Owner decision 1, a row's money cap on a sale.** A transfer of goods `for` a deal that has a price reads as that deal's money total at the quantity it moves (a 1-loaf sale at £3 is £3, under "up to £300 a deal"); a transfer of goods with no priced deal has no money total, so its amount stays another kind than the cap and is above it (story C21 of stage 6 is unchanged: nothing fills the silence of a price). The same rule counts a row's `limit`. A sale of 200 loaves at £3 is £600 and the row does not hold. Pinned: `7-owner` (D1).

**S14. Owner decision 2, `binds` of a draft `as` a circle.** The draft has no hand yet: it is read as her signed form would be. A draft that states no `seq` or `prev` is placed next on its author's line (the key it names, else her first key). It binds where her row would hold for it (or every owner signs it) and something of the circle's moves; an accept `as` a circle binds only where the row would hold; a draft not `as` a circle is read as before. Pinned: `7-owner` (D2).

**S15. Owner decision 3, no roles.** A signal's `by` that names `x#y` names no signer (it does not hold); a signal with more than one `by` needs `signers`; `members_then` of a name that is no circle is `[]`; `count_of` reads a whole number only. The `RX.role_ref` reads in a repeat's `by` and a price figure's `by` are gone (every name is an id). Pinned: `7-owner` (D3).

**S16. A5, what a removed field leaves.** `withheld` is no field (a promise carrying it is `undeclared_field`), and no header carries it; `terms.show` is no term (`undeclared_field`); the stage has no `show`; consent reads `yes` and `stop` only. Pinned: `7-privacy` (A5), `7-deletions`.

**S17. The dealer (D4, by the dealer builder).** Message shape: the `.foodblock` attachment `{ messages, ids? }`, the subject last, its pieces before it; the ids ride beside it (`{ block, signature }` carries none, so tampering shows as `bad_hash` against a sent id). Item 5's terms it reads: `price`, `quantity`, `expires`, `pay_by`, `deliver_by`, `step`; any other term is `term_not_read`, a schema `schema_not_read`, a condition `condition_not_read` (the three names are the oracle's own). A first promise whose quantity is a range is not accepted (`nothing`); a payment it did not itself count as received gets no `accepted` with `covers` (`nothing`); a block it cannot open waits (`waits`); an order under a grant it holds and passes (`under_ok`) is answered, one it cannot check is `ask_own_key`; a sealed accept copies the order's audience, its nonce the first 32 hex of the order's hash. Story 9 reads "Harry's transfer and Amara's `accepted` with `covers`" as Harry's goods transfer `for` the order carrying `covers`, plus Amara's `accepted` of it. Not built: handing over goods (item 7's other half), item 4's genesis line. Pinned: `7-dealer` (twelve stories, D1).

**S18. The read-back (C3, C4, by the read-back builder).** A reading or renderer is named by the SHA-256 of the file's bytes alone (SILENT 1), the files being JavaScript modules under `spec/oracle/readback/` (SILENT 2); the text is the renderer's words, one space, the digits, and the digest the SHA-256 of that text; redo runs on the inputs alone and names a file whose bytes do not hash to its name in `lacks`. The person it is read back to is the readback's `refs.to`. A person's name is her own actor block that `updates` her genesis (a genesis cannot carry a name: `bad_genesis`); two that do not see each other give no name. Instance lines come from typed refs, not from `gives` (which drops "not his to give"). The checked text copies names and units as signed ("300 GBP"), repeats a name where it would be a pronoun, shows line 10 for money kinds on every priced deal, prints line 14 as "A and B must both hear each deal. If either is silent, deals wait.", takes "FoodX's promise" (line 15) as a held promise by the one clock's owner `for` the grant that carries `terms.backing`, and keeps the table's "only" in lines 15 and 18 (it reads the ban as "her word only"). `en-sms` has its own shorter phrasing, at most 160 GSM-7 characters. Pinned: `7-readback`, `7-readback-lines`, `7-readback-random`.
