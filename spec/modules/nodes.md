# Nodes

A convention. It changes no word (core.md, section 10); two nodes that share it can talk. Anyone can leave a node with everything they signed. Two messages, Pull and Push, work over any link. A block is valid whatever its type (core.md, section 8); whether a node stores it or sends it on is that node's own promise (A node's word, below).

## Messages

A message is canonical JSON, whole (canonical.md, On the wire). Every shape is in `protocol.json` (`messages`); a message carries no version. Block messages are in core.md, sealed ones in privacy.md.
- A **signed request** adds `signer`, `node` (the node it is for), a proof against replay, and `signature`. The signature is over the canonical JSON of the request without `signature`, by a key that speaks for the signer (identity.md; the door's `live_keys`). A signed request from a signer the node does not hold is checked against the pieces the push carries.
- **The proof against replay** carries no clock. Either `counter`, an integer 0 to 2^53 - 1 (core.md, section 3) that the signing key raises with every request to that node, which keeps the highest per key and refuses an equal or lower one; or `challenge`, a value the node issued for this one request (`GET` its `challenge` endpoint), which it refuses if unissued or used.
- In a pull answer, `request` is the bare SHA-256 hex (whatever the suite) of the canonical JSON of the whole signed request, `signature` included, and `n` is each block's arrival number on the log the answer names (The arrival log). The answer has `log` only when the request names one; a block with no receipt on that log has no arrival number there and is not served under it. A push answer is `{ node, receipt, taken, held, unjudged, refused, unread, equivocations, signature }`; every key is always present but `receipt` and `held`, and an empty list is `[]`. `receipt` is the receipt of what the push added, as a sealed block message, left out when the push added nothing or the node signs none. `held` lists the blocks already held, ascending by hash. Giving either is the node's word (below).

## The arrival log

A node says "I hold this" as anyone says anything: with a signed block on its own line.
- A **door log** is the line of one key of the node's holder that it keeps for one person's door and for nothing else. Each block on it is a receipt (blocks.md, A named clock) of what pushes added for that door: `refs.derives_from` the blocks, `refs.subject` the door's person, sealed to her and to the pusher (privacy.md). A receipt sealed to a pusher names only what that pusher's push added. Its `seq` may skip (`skip`), so a number shows order and never a count.
- A node that keeps a log of public blocks (an index) keeps it on another key, with public receipts: one key writes public blocks or sealed blocks, never both.
- A log is named by the id of the block that brought its key in. A block's **arrival number** on a log is the `seq` of the first receipt on it that names the block.
- A block the node refused, or never showed the door's person, takes no receipt. A node that stops holding a block says so on the same log: an `observe` of kind `dropped`, `refs.derives_from` the blocks, or receipts, which drops every block they name that the door's person neither signed nor answered.
- A receipt on a door log after a receipt of her address that no longer names this node is no taking at her door (Her address).
- A push that got no receipt has not been shown to be taken.

**Three things are shown by signed words alone** (door op `log_shown`):
- **Left out.** A receipt puts a block at a number; a pull answer signed for the same log, by a key that speaks for its node and naming this request's hash, spans that number (the request's `since` is below it and the answer's `next` at or above it); the block matches the request's filter as the asker may see it (whole when it is public or she signed it, else by its header; a block the checker does not hold matches only a request with no filter); no `dropped` at or below `next` drops it, by naming it or its receipt; and the block, or its header, is not in the answer. A receipt counts here only as a valid body on the log: one held as its header names nothing.
- **Stopped short.** A request names in `seen` a receipt on the log; the answer, signed as above, has `next` below that receipt's `seq` and equal to the request's `since`.
- **Two logs.** Two receipts of one log's key that name one `prev` or state one `seq`: a pair (Equivocation).

Each is a fact about what the node signed, never a verdict. What follows for the node is whatever its own word, or a deal its holder signed, says.

## Pull

- `log` names the log the asker reads; a door log is served only to a signed asker it is sealed to. `since` is an arrival number on that log (exclusive; 0 from the start). With no `log` (the node keeps none, or the asker names none), `since` and `n` are the node's own word: numbers it keeps for itself, 1, 2, 3 in the order it took blocks, which show nothing. `seen` is the id of a receipt on that log the asker holds: an answer to it is the node's word that it read its log at least that far.
- `filter` matches exactly on `type`, `kind`, `author`, `hash`, `record` (a record's first hash: every version), `marks` (`{ scheme, value }`) and `refs` (`{ key: hash }`). Keys AND together. An unknown key, a `refs` or `marks` of the wrong shape, or a filter that is not an object matches nothing; no filter matches every block. A filter reads only what the asker may see: a public block whole; a sealed block only for a signed asker the node holds a copy for, whole where the node holds its body, else by its header (`author`, `prev`, `seq`, `hash`); for anyone else a sealed block matches no filter.
- `heads: true` returns only the matches that no other match names by `prev` or `updates`.
- `limit` is the asker's wish; the responder cuts it to its own cap (A node's word).
- The answer is the matches in arrival order with their numbers, and `next`: the number of the last match when the answer is full, else the last number the node read. A node reads a bounded window per pull, so an answer with no match still moves on. The answer names its `log`. A puller moves past a block it refuses or cannot yet judge: `next` is a place on the peer's log, never a claim that the puller took every block before it.
- **A fork's proof.** A node that serves a pair's proof (A node's word) includes both blocks of a pair it holds in any answer that includes either, whatever the filter, `limit` or `since`. A pair is two blocks of one key on one `prev` or at one `seq` (Equivocation). The pair is in addition to `limit`. A sealed block of a pair goes as the asker may see it.
- An unsigned pull gets public blocks. A signed pull also gets each sealed block the node holds a copy of for the asker: its header, its signature and that copy. Nothing of a sealed block goes to any other asker, and for anyone else it matches no filter.

## Push

A sealed copy may say which of the receiving node's people it is for (`for`: `{ hash: [id] }`). That id may be one made for this counterparty (privacy.md, Keeping apart). It is all a carrier is told of the reader; a copy wrapped to a mailbox tells it only the mailbox. By carrying it also sees who wrote the block, the copy's size and when. A carrier is bound to silence on none of it unless it signed so. A sealed block arrives as its header message, which `valid` judges as any block (core.md, section 8).
- `strict_push` answers one list per message, plus one field for a refusal of the whole push: `{ refused, messages: [] }`, or `{ messages }` with `refused` left out where the push is not refused. The door takes a push as bytes, so no caller decodes text before the core reads it.
- **A push is one message,** read by the wire rule (canonical.md, On the wire): bytes that are not canonical refuse the whole push (`not_canonical`), and nothing in it is judged. A block whose own bytes break strict writing is refused alone.
- **A node judges each block on its pieces.** Every block of a push is judged by `valid` against what the node holds and the rest of the push. One whose pieces are not all there is unjudged (`unjudged`, with the pieces it lacks as `needs`; a block that waits only on a suite this reader does not know needs `[]`); nothing else holds a block back. A block whose body the node holds is nothing new and is not listed; so is a header that describes a body held (privacy.md, The header). A valid block is taken; it is then read (`read`), and one that is not read is listed in `unread` with its codes and held as its header. An accept pushed alone is valid on its own pieces, and read once the offer is held.
- **Which pushes a node keeps a sealed copy from is its admission rule** (Admission): a signed push, a key the reader gave the pusher, or any other it states. A handed-on copy never takes the place of the author's. A node sent an opened body as a plain message from anyone but its author keeps it as a copy for the reader the push names, and serves it to no one else.
- **A body beats a false header.** When a block arrives whose hash the node holds as a header naming another author, key, `seq` or `prev`, `valid` judges the block, the answer lists the hash in `false_headers`, and the node keeps the block in the header's place.
- **Unjudged.** How many blocks may stay unjudged for one author, from whom, and for how long is the node's own word. A node fetches a missing piece from the signer of a signed push, or from a route in an address block its author signed.
- **The answer.** `taken` and `refused` are ascending by hash, a block's codes in `protocol.json` order; `unjudged` and `unread` ascending by hash, each `needs` and `codes` in order; what is taken never depends on the order of a push. `equivocations` is always present: the pairs (Equivocation) of each group of blocks of one key on one `prev` or at one `seq` that a block of this push belongs to, counting only blocks that speak for their author once the push is taken (a block that does not count for its author forms no pair: identity.md, A suite move). The pairs are a **star**: each block of the push paired with the lowest hash of its group, and a block that is that lowest paired with each other. Each pair is sorted as text, and so is the list. **Both blocks of a pair are kept.** Whether a node takes them is its own promise: a node that does not takes neither when both arrive in one push, and not a block that forks one already held. Such a block is neither refused nor unjudged. A sealed pair's proof is its two headers.

**Signed answers.** A node signs every answer with any live signing key of its holder (a person or a machine): the genesis key or one brought in by a key grant. The signature is in that key's algorithm over the canonical JSON of the answer without `signature`. Discovery's `node` is the holder's id; there is no separate node actor.

## Admission

A node admits by its owner's published rule, an `observe` of kind `admission` whose hash discovery names, with state `{ parties, per_stranger, order_channel }`, each optional: ids always admitted, blocks a day from anyone else, and the types an autonomous system may send first (consent.md).
- `per_stranger` is the most **asks** one day may bring from each sender not in `parties`, counted for that sender alone. An ask is a block that names one of the node's people in a ref other than `refs.author`; a block's pieces, and the blocks its answer reads, are never counted, and a block that is no ask is never refused by the count. When the node has taken that many asks today from that sender, the next is `not_admitted` (`asks_today >= per_stranger`). A key costs nothing, so a count for each sender bounds no flood: a door that wants a bound states a total (below).
- With no `per_stranger`, or no rule, the node's own software chooses; the protocol has no admission default. The reference server's choice comes from its owner's configuration (`PER_STRANGER`), applies only where the rule names none, and is published under `software_chose`: that node's word, never the protocol's.
- **A total for all strangers.** A node may also publish its own most asks a day from every sender outside `parties` together (`strangers_per_day`), so that a million free keys share one allowance and do not each get one. It is the node's own word (A node's word), published in its admission document under `software_chose`, never in the rule and never a default; the core reads none. The reference server requires its owner to state it (`STRANGERS_PER_DAY`) and refuses to start without.
- `order_channel` is a list of types. A node whose rule states one may refuse (`not_human`; consent.md) a first block to a stranger that an autonomous system signed outside it. It reads only what is signed (the declared genesis `kind`, a named grant) and never infers what an author is. It never refuses a block for a STOP: the block is kept and the fold reads it as stopped. A node may decline to relay its body to the stopped party.
- A listed party is exempt from the count only for a block signed by a key that still speaks for them (folds.md); any other is admitted as anyone's, so a thief with an old key cannot fill the store under her name.
- A rule may also say where the node stores blocks (profiles/residency.md) and take earnest money (profiles/earnest.md). A node may refuse any push.

## A node's word

What a node does with a block beyond holding it and sending it on is its own signed word, binds it alone, and is never a protocol duty. Each such word is stated where it lives. The core fills none in: a call that asks the core for a node's answer states each choice.

## A host

A **host** is a machine that runs someone's node. A node is her key, not a place: the host is where her blocks are kept and served, and she may move to another at any time. These are the rules a host follows to be a host she can leave. Every line is the host's own signed word (A node's word): the protocol fills in none, and a host that states a line is bound by it and a host that states none is bound by nothing.
- **Her address.** Her address is her id, with an optional name that is checked both ways (her id's `observe` of kind `profile` names it and the name's own record names her id; a reader trusts only a name both sides say). It is never a name another alone grants. "I now live here" is an `observe` of kind `address` she signs: `state.routes`, a list of `{ via, to }`, where `via` is how it is carried (`host`, `sms`, `email` or any open label) and `to` where it is carried to (for `host`, the host's node id and its URL). A new address is a new block that `updates` the old; the head of the chain (the block no other `updates`) is her current address. Two heads that do not see each other both stand: a sender may use either, and no hash picks one. She lists the new route before she drops the old, so there is an overlap. An address may state `until`: by her word, it names no route after that time. The move needs only her key and nothing from the old host. A host keeps and serves her address blocks like any block, by a pull that filters on `kind` and `author` with `heads`; no one keeps a directory. An address may be sealed: an address for one counterparty reaches only them.
- **How a node is woken.** A host wakes her node when something waits for it: a block arrives that names her, or a time she signed comes due. A **wake** is a bare call, not a block: `{ for }`, her id, posted to the `wake` URL its promise block states, which a host that states the line accepts for an id it keeps. It carries no power and no word: the node learns what happened only from signed blocks it pulls, so a forged or repeated wake costs one pull. A host may rate-limit or refuse a wake (A node's word). Which of her machines runs the node, and what it does when woken, is the host's and hers, not the protocol's.
- **The host's promise.** A host signs its promise as an `observe` of kind `host_promise` in its own name (its own key, never hers), with `state` lines it chooses: what it stores (public blocks whole, sealed blocks as header plus unopened envelopes, append-only), that it syncs (takes what a peer has, gives what the peer lacks, every block through the same check), that it keeps her reachable (serves her address and the `wake` endpoint, and after she moves answers with her new address block for a time it states), that it never holds her key (it signs only its own pull answers and promise, and a basic phone's witness blocks in its own name, identity.md, A person with no key), and that it keeps one door log for each person it keeps a door for, on a key of its own for that door, every receipt naming her in `refs.subject` and sealed to her and to the pusher, that it tells no one what it carries (who wrote, whom a copy was for, how big, when), as a promise not to do with a stake and a judge (promises.md, A promise not to do), kept for a time it states, and that it lets her leave (a complete export on request, serving the move, no wait before she goes beyond a forfeit sum she signed). The state also names the URLs it serves (`wake`, `export`, `import`), because discovery's endpoints are a closed list (the protocol's own three). A host publishes the block beside discovery; the reference host serves it in the `.well-known/foodblock` answer, under `promise`, outside the closed discovery fields.
- **Her record at a host** is every block her door log names, every block she signed that the host holds, each one's pieces, the lines each one's answers read, from the block back to their starts (folds.md, A line), and the door log. It leaves as `{ format: "application/foodblock+json", messages }`, canonical JSON, each block exactly as signed; another author's sealed block as its header, with the unopened envelopes for the one they are sealed to. **An export is whole** when the door log runs unbroken from its first block to a block of it she holds; every block a receipt on it names is in it, or dropped, itself or by its receipt, by a `dropped` on the log; every piece of every block in it is in it; and, for each answer a fold gives of a block in it, the line that fold reads, from that block back to the fold's own start and no further (folds.md, What is left; each fold names its start), lacks no block a receipt on the log names, so no such answer is `not_shown` for want of one. She, and anyone she hands the log to, checks this from the document with the door op `export_whole`, the receipts opened. It loads by the rule of a push: each block is judged alone, and one the new host does not take holds back only the blocks it is a piece of. **She need not ask to leave:** a pull of her door log `since` her last receipt brings the same blocks.

## Discovery

A node publishes `.well-known/foodblock`: `{ protocol: "foodblock", reads, node, admission, endpoints: { pull, push, challenge }, log, signature }`. `reads` lists the rule sets the node runs (core.md, section 11): it lists one only when it runs a build made from that set's files. An index that answers a fold names in its signed answer the rule sets it runs (`reads`) and lists `lacks`; the answer is its own word. `log` names the node's public log, when it keeps one. The document is signed like any answer (nodes.md, Invariants). Nodes are found as email addresses are: given directly, listed in any directory, or followed from a ref. People are found by phone number or payment address (profiles/addressing.md). Nearby, a node may answer the same document or announce a short form of it (`protocol.json`, `local_discovery`: mDNS / DNS-SD, name `_foodblock._tcp`). None is required; a node with no peers is valid.

## Equivocation

A pair is two blocks with one signing key and one `prev` or one `seq` (core.md, invariant 3); it needs no line, only the two (or their headers). Blocks of two keys are never a pair. A sealed block known by its header alone pairs the same way (privacy.md). A node keeps both. What a fold does with a pair is in folds.md.

## Finding

A pull with a filter returns every match, unranked. Ranking is the reader's own node's; the protocol says nothing about it. Any node may be an **index**, serving others' public records. An index's answer to a find is its own selection: no reader can show it complete. A seller who holds an index's receipt tests his own listing by a pull on his own id (Left out). A reader checks a public line it holds for gaps and pairs; a sealed line is checked by those it is sealed to, and a pair on it is seen only by one who holds both branches.

## What never becomes a block

Only signed blocks cross between nodes. Drafts, goals, limits, budgets, private rules, rankings and what a person loves stay on their node. The protocol depends on no one transport: email, messaging and links are envelopes (transport.md); the compact form is in encoding.md.

## Invariants

Holds: Every node answer a reader relies on is signed by the node.
