# Necessity

The evidence that each part of the protocol is hard to vary. Generated by `node tools/necessity.cjs` from `spec/protocol.json` and the vectors; `node tools/necessity.cjs --check` (and `test/necessity.cjs`) fails if this page is out of date or a part has no test. Do not edit it by hand.

**Method.** For each listed thing, a scratch copy of the spec has that one thing deleted from `protocol.json`, and two engines run every vector: the spec-only oracle (`spec/oracle/run.cjs`, then the audit worlds `test/audit/run.cjs`, where the SDK and the oracle must give the same answer) and the Rust core (`cargo test --test vectors`, built from the changed list). For a verb or ref key a fold reads by name, the oracle is also made blind to that key. What fails is shown (`oracle ...` and `audit ...` are checks of the oracle and the audit; `core N vectors` is the Rust core). `required` and `needs` in `protocol.json` are prose summaries of core.md sections 7 and 5, read by no engine, so they are not mutated; refusal vectors carry them. "Carry it" lists the vectors whose blocks hold the thing, from a scan of `spec/vectors.json`.

- **COVERED**: deleting it fails at least one vector or audit check.
- **USED**: nothing fails, but a vector's valid block carries it (shown working, not enforced).
- **UNTESTED**: code reads it and no vector carries it. It needs a vector.
- **DEAD**: nothing reads it and no vector carries it. Delete it.
- **STRUCTURAL**: the engine cannot start without it.

**Summary.** 100 listed things: 100 covered, 0 used, 0 structural, 0 untested, 0 dead. 31 numbered invariants: 31 stated in the spec and carried by a vector.
